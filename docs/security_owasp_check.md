# OWASP 보안 점검 (2026-11-19)

기준: 영상 「AI로 바이브 코딩한다면 무조건 봐야 할 웹 보안 필수 가이드 (세션 vs JWT vs OAuth)」(김웅곤)의
**OWASP AI 코딩 시 놓치기 쉬운 취약점 점검** 10개 + **보안의 창과 방패**(XSS · CSRF · MITM) + **토큰 보관·이중 잠금 전략**.

점검 방법
- 코드 읽기 (`server/*.js`, `src/`)
- 배포 주소 https://yjmarket.up.railway.app 에 **읽기만 하는** 요청 (헤더, 막혀야 할 주소)
- 시험 스크립트: `npm run test-authz` (새로 만듦), `npm run test-session` (새로 만듦), 기존 결제·주문·환불 시험

## 이번에 고친 것

1. **관리자·판매자 쿠키 SameSite=Strict** (`server/auth.js` setCookie)
   - 다른 사이트에서 넘어온 요청에는 관리자 쿠키가 아예 붙지 않는다. Origin 검사와 이중 잠금.
   - 손님 쿠키는 Lax 유지: 카카오·네이버 로그인, 토스 결제에서 돌아올 때 로그인이 이어져야 해서.
2. **세션 타임아웃** (`STAFF_IDLE_MINUTES`, 기본 120분)
   - 관리자·판매자가 2시간 동안 아무 API 도 쓰지 않으면 로그인이 끊긴다. 쓰는 중이면 5분마다 '마지막으로 쓴 시각'만 갱신, 8시간 만료는 그대로.
   - 예전 쿠키(시각 없음)는 로그인한 때부터 센다.
3. **로그인 잠금 알림** (`security_login_locked`)
   - 비밀번호·인증 코드를 여러 번 틀려 잠기면 계정 주인(관리자 또는 그 농가)에게 알림. 메일 설정이 없어도 [설정 > 알림 기록]에 남는다. 잠금 시간 동안 한 번만.
4. **Permissions-Policy** 머리말: 카메라·마이크·위치·USB 등 쓰지 않는 브라우저 기능을 끈다 (결제는 토스 결제창 때문에 막지 않음).
5. **CI 에 자동 점검 3개 추가**: 라이브러리 취약점(높음 이상), 권한 검사(새 주소에 로그인 검사를 빠뜨리면 실패), 로그인 보안 시험.

## 회사 몫으로 남는 것
- 자체 도메인을 연결하면 HSTS `includeSubDomains; preload` 추가
- 메일(SMTP)을 연결하면 잠금·2단계 인증 알림이 실제 메일로 간다 (지금은 알림 기록에만)
- 운영 관리자 접속을 사무실로 묶으려면 `ADMIN_ALLOWED_IPS` 설정
