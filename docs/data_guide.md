# 데이터 안내 — 누가 어떤 파일을 바꾸나

지금 `data/` 의 파일은 모두 이희석이 만든 **[예시] 데이터**입니다. 팀원 데이터가 오면 같은 칸 이름으로 바꿔 넣고 `npm run load-data` 를 다시 실행합니다. 검사 결과는 `docs/data_report.md` 에 담당자별로 나옵니다.

| 파일 | 담당 | 내용 | 지금 들어 있는 것 |
|---|---|---|---|
| `items.csv` | 김가온(과일·채소), 이현서(가공품) | 품목 기준표: 보관법, 신선도 단계, 알레르기, 먹으면 안 되는 신호, 레시피 | 사과, 배, 복숭아, 고구마, 당근, 감자, 배즙, 매실청, 포도잼 (9개) |
| `sellers.csv` | 이다현 | 판매 농가 소개와 산지 이야기 | 회사 직영 + 가상 농가 2곳 |
| `tags.csv` | 이희석 | 추천·검색용 태그 | 14개 |
| `products.csv` | 김재훈 | 상품: 가격, 단위, 재고, 당도, 수확일, 판매 링크, 태그 | 10개 (시험용 3개 포함) |
| `product_options.csv` | 김재훈 | 판매 옵션: 상품 코드, 옵션 이름, 가격, 재고 (같은 상품을 5kg·10kg처럼 나눠 팔 때) | `apple_10kg` 의 5kg·10kg 옵션 2개 |
| `questions.csv` | 박형우 | 상품 Q&A 예시 | 6개 |
| `chatbot_tests.csv` | 박형우 | 챗봇 시험 질문과 맞는 답 | 89개 |
| 사진 | 심지은 | 상품 사진 (파일 이름 = 상품 코드) | 아직 없음 |

## 꼭 지킬 것

1. 모르는 칸은 비워 두기. 0 쓰지 않기
2. 지어낸 데이터는 이름 앞에 [예시]
3. 숫자 칸은 숫자만 (가격 32000, 당도 12.5)
4. 날짜는 2026-10-17 형식
5. 사실 정보(보관법, 알레르기 등)에는 source 칸에 출처
6. 효능 표현 쓰지 않기 (면역력, 다이어트, 치료, 예방 등)
7. 한 칸에 여러 값은 | 로 구분 (생으로|샐러드)
8. 코드는 영문 소문자·숫자·밑줄만, 한 번 정하면 바꾸지 않기
9. 레시피는 `제목:재료:방법` 을 | 로 이어서. 상세 화면 레시피 카드에 실제 사진을 쓰려면 사진을 `public/recipe-photos/` 에 영문·숫자 파일 이름으로 넣고 끝에 주소를 붙인다: `키위 요거트:참다래·요거트:썰어서 올리기:/recipe-photos/kiwi-yogurt.webp`. 사진이 없으면 요리 종류(샐러드·음료·수프·잼 등)에 맞는 기본 그림(`public/recipe-art`, 직접 그린 그림)이 나온다. 남이 찍은 사진은 사용 허락·출처를 확인하고 쓴다
10. 판매 옵션은 `product_options.csv` 에 한 줄씩 (옵션 이름에 양을 적기: `5kg 1박스`). 옵션이 있는 상품은 `products.csv` 의 가격·재고를 판매 중 옵션의 최저가·재고 합으로 다시 계산한다. 표에서 옵션 줄을 지우면 주문 기록이 없는 옵션은 지우고, 있는 옵션은 판매 중지로 남긴다

## 사이트 시험용 상품 (지우지 않기)

| 상품 | 시험하는 것 |
|---|---|
| `pear_5kg` 재고 0 | 품절 표시, 추천에서 빠지는지 |
| `sweet_potato_5kg`·`potato_5kg`·`carrot_3kg` 당도 빈칸 | 당도 줄이 숨겨지는지, 챗봇이 당도를 지어내지 않는지 |
| `peach_4kg` 품종 장호원황도 | 품종별 공식 기준으로 당도 등급이 붙는지 |
| `apple_10kg` 옵션 5kg·10kg | 목록 "~부터" 가격, 상세 옵션 고르기, 옵션별 재고·주문, 챗봇 옵션별 가격 |

## 식품팀 검수가 필요한 곳

`items.csv` 의 보관법·신선도 일수·알레르기·먹으면 안 되는 신호는 모두 예시 값입니다. `reviewed_by` 가 비어 있으면 검수 전입니다. 특히:
- 감자: 싹·초록색 껍질 주의 문구
- 매실청: 매실 씨앗과 숙성 기간 주의 문구
- 복숭아: 알레르기 표시
