# 상담 챗봇 벡터 검색(RAG)

규칙이 못 잡은 질문의 근거를 찾아 주는 층이다. 규칙을 대신하지 않는다.

## 답이 나가는 순서

1. 건강, 환불, 주문, 결제, 가격, 재고: 지금처럼 규칙과 DB 값으로 답한다
2. 규칙이 못 잡으면 벡터 검색으로 자료를 찾는다
3. 아주 확실하면 찾은 글을 그대로 보여 주고, [AI에게 물어보기]도 함께 둔다
4. 아니면 전처럼 안내한다. 품목을 말하지 않았어도 관련 자료를 찾았으면 AI 버튼을 보여 준다
5. 버튼을 누르면 찾은 자료를 AI에게 함께 넘기고, 답 검사를 지나야 내보낸다

## 읽는 자료

| 자료 | 조건 | 찾은 글을 그대로 보여 주는가 |
|---|---|---|
| 품목 보관법, 상태별 활용, 레시피, 알레르기, 먹으면 안 되는 신호 | 검수 전 품목 제외 | 예 |
| 교환·환불, 배송, 주문, 연락처 안내 | `server/policy.js` 값 | 예 |
| 상품 Q&A | 답이 있고 숨기지 않은 것, 판매 중 상품 | 예 |
| 상품 소개, 설명, 자주 묻는 질문 | 판매 중 상품 | 아니요 (판매자 글이라 AI 자료로만) |
| 농가 소개 | 판매 중 상품이 있는 농가 | 아니요 (판매자 글이라 AI 자료로만) |

가격, 재고, 품절, 주문 상태는 넣지 않는다. 답할 때마다 DB에서 읽는다.

## 자동 반영

- 관리자, 판매자 화면에서 무언가 저장하면 3초 뒤 자료를 다시 맞춘다. 글이 바뀐 조각만 다시 계산한다
- 서버를 켤 때와 10분마다 한 번 더 맞춘다 (`load-data`처럼 DB를 직접 고친 경우)
- 판매 중지한 상품은 다시 계산되기 전이라도 검색할 때 걸러서 바로 안 나온다
- 확인: `npm run test-rag`

## 찾은 글을 답으로 내는 조건

모두 맞아야 한다. 하나라도 어긋나면 글을 내지 않는다.

- 점수 0.60 이상, 2위와 0.03 이상 차이
- 질문에서 품목 이름을 뺀 낱말이 글에 15% 이상 나옴 (이름만 같아도 점수가 올라가서 넣었다)
- "좋아요, 괜찮아요, 먹어도" 같은 판단을 묻는 말이 없음
- 먹으면 안 되는 신호 글은 상한 것을 물었을 때만
- 외부 연락처와 금지어가 없음

## 모델

벡터 계산은 OpenRouter의 `baai/bge-m3`로 보낸다. 처음에는 서버 안에서 계산했는데, 메모리를 1.2GB 넘게 써서 실습 계정 한도(5GB)에 걸려 서버가 느려졌다. 호출이 실패하거나 4초를 넘기면 벡터 검색 없이 답한다.

말 바꾼 질문 24개로 비교했다 (`npm run rag-bakeoff -- 모델 이름`).

| 방식 | 1위 적중 | 3위 안 적중 | 100만 토큰당 |
|---|---|---|---|
| 글자 비교 (지금 방식) | 13 | 17 | 0 |
| openai/text-embedding-3-small | 13 | 18 | 0.02달러 |
| qwen/qwen3-embedding-8b | 11 | 21 | 0.01달러 |
| intfloat/multilingual-e5-large | 20 | 22 | 0.01달러 |
| baai/bge-m3 (선택) | 21 | 22 | 0.01달러 |

## 비용과 개인정보

- 벡터 계산: 질문 하나에 약 30토큰이라 100만 건에 약 0.3달러다. 같은 질문은 1시간 기억한다
- AI 버튼을 눌렀을 때: 찾은 조각 최대 5개가 입력에 더해진다
- `anthropic/claude-haiku-5.5` 기준 AI 답 하나는 입력 약 2,800토큰, 출력 약 470토큰으로 약 0.0005달러다 (2026-11-05 가격)
- 규칙으로 바로 답하지 못한 질문은 AI 버튼을 누르지 않아도 벡터 계산을 위해 OpenRouter(미국)로 나간다. 전화번호, 이메일, 주민등록번호, 주문번호는 보내기 전에 가린다
- 쇼핑몰 서버의 메모리와 설치 용량은 거의 늘지 않는다
- 끄려면 `.env`에 `RAG_ENABLED=0`을 넣는다

## 결과 (2026-11-05, 예시 데이터)

| 측정 | 벡터 검색 없음 | 벡터 검색 |
|---|---|---|
| Claude가 쓴 말 바꾼 질문 52개: 정답 자료 1위 | 28 | 46 |
| 같은 질문: 정답 자료 3위 안 | 40 | 50 |
| 찾은 글을 답으로 냄 | - | 14개 (틀림 0) |
| 답 없는 질문 25개에 답함 | - | 0 |
| 챗봇 평가 321개 (AI 없이): 정답 / 자신 있게 틀림 | 210 / 0 | 210 / 0 |
| 팀원 질문 100개 (AI 없이): AI 버튼이 새로 생김 | - | 8개 |

- **검색은 좋아졌지만 AI 없이 맞는 답은 늘지 않았다.** 자료가 적고, 실제 손님 말투에서 틀리지 않게 조건을 조였기 때문이다
- 처음 조건에서는 "사과 맛잇는거로 보내줘"에 먹으면 안 되는 신호가 나갔다. 그래서 낱말 조건과 상한 것을 물었을 때만이라는 조건을 넣었다
- 기준 0.55에서는 "결제하고 언제 출발해요"에 환불 시점 안내가 나가서 0.60으로 올렸다. 그래서 test 질문의 값은 처음 보는 질문의 값이 아니다
- AI 답은 질문 6개를 Haiku로 읽었다. 주말 출고는 자료로 맞게 답했고, 무농약, 제주 배송, 해외 배송은 자료에 없다고 답했으며, 관절 효능은 말하지 않았다. 부침개 질문은 찾은 5개에 감자전 레시피가 없어서 "정보가 없다"고 답했다. 벡터 검색이 놓친 경우다
- 무료 모델은 같은 묶음에서 호출 실패(429, 502)와 한자 섞임이 자주 나왔다

## 못 한 것

- 실제 회사 자료가 없다. 포장, 제주 배송, 무농약처럼 자료에 없는 질문은 찾아도 답이 없다
- AI 답변은 몇 개만 읽었고 벡터 검색 전후를 같은 모델로 비교하지 않았다
- 조각이 수천 개를 넘을 때 속도는 재지 않았다. 지금은 앱에서 계산한다 (실습 DB에 pgvector가 없다)
