## 2. 왜 이 조합인가

우리 서버는 아래 이유로 서버리스(Netlify·Vercel)에 그대로 올릴 수 없다.

- **반복 작업 3개**: 미결제 주문 정리, 상담 자료(RAG) 10분마다 갱신, 보관 기간 지난 개인정보 6시간마다 삭제.
- **사진 저장**: 관리자·판매자가 올린 사진을 서버 디스크에 저장한다(상품 38개의 당도계 사진 등).
- **긴 요청**: AI 상품 소개 초안처럼 30초를 넘을 수 있는 요청이 있다.

그래서 서버를 계속 켜 두는 상시 서버가 필요하다. 앱·DB·볼륨을 한 곳에서 관리할 수 있는 Railway를 골랐다.

(비교용으로 8주차 오프라인 실습에서 개인 앱 my-intro를 Netlify + Supabase로 올려 봤다. 가벼운 앱은 그 조합이 무료로 충분했지만, 위 세 가지 때문에 쇼핑몰에는 맞지 않았다.)

배포 전 실습서버에서 확인한 것 (2026-11-12):
- 운영 모드(`NODE_ENV=production npm start`)로 켜져 화면·API·상태 확인 주소(`/api/health`)가 응답한다.
- 사진 폴더를 설정값(볼륨 경로)으로 바꿔도 사진이 나온다.
- DB: 15MB, 확장 없음, `farm` 스키마 하나 → `pg_dump -n farm`으로 그대로 옮길 수 있다.

DB 옮기기 (2026-11-14):
- 실습서버 개발 DB의 `farm` 스키마를 Railway PostgreSQL로 옮겼다. 옮긴 표의 행 수가 모두 같았다 (상품 138, 품목 27, 상담 자료 328 등).
- 공개 데모라 **손님·주문·기록 표는 데이터를 옮기지 않았다** (실습서버 DB에 실제처럼 보이는 메일이 섞여 있음). 상품 Q&A는 연락처와 회원 연결을 지우고 옮겼다.

## 5. 시험하며 알게 된 것

| 문제 | 원인 | 해결 |
|---|---|---|
| 배포 후 502 "Application failed to respond" | `DATABASE_URL`이 비어 앱이 DB를 자기 자신(127.0.0.1)에서 찾다가 꺼짐 | 변수를 다시 넣음 |
| `${{Postgres.DATABASE_URL}}` 참조가 빈 값, 내부 주소 `postgres.railway.internal`도 못 찾음(ENOTFOUND) | 앱과 DB가 **서로 다른 Railway 프로젝트**에 만들어졌다. 참조와 내부 주소는 같은 프로젝트·환경 안에서만 통한다 | 앱을 DB와 같은 프로젝트에 새로 만들어 내부 주소로 연결 (11/14 15:38). 옛 프로젝트는 지우고 DB 공개 접속을 껐다 |
| 첫 배포에서 배송비 안내가 옛 정책 | 시험용 브랜치가 회사 피드백 반영보다 먼저 만든 브랜치였다 | 배포 브랜치를 `main`으로 바꿈 |

## 6. 한 달 운영 조건

| 조건 | 대응 |
|---|---|
| 잠듦·일시 정지 | Railway 상시 서버는 잠들지 않음 (Render 무료·Supabase 무료와 다른 점) |
| 크레딧·사용량 | 주 1회 Railway 사용량, OpenRouter 사용량 확인 |
| AI 비용 폭주 | OpenRouter 키 사용 한도 + 코드의 하루 AI 호출 상한 (배포 설정: 전체 100회, 1인 10회) |
| 데이터 | 시험용 손님·주문만 (실제 개인정보 넣지 않음), 주 1회 pg_dump 백업 |
| 장애 | Deployments에서 이전 배포로 Rollback 후 코드 revert |
| 종료 | 한 달 뒤 키 재발급·프로젝트 정리, 코드와 문서를 회사에 전달 |

## 8. 검토했지만 고르지 않은 대안

| 대안 | 고르지 않은 이유 |
|---|---|
| Netlify + Supabase | 반복 작업·디스크 저장·30초 제한 때문에 서버 구조를 크게 바꿔야 함. Supabase 무료는 7일 쓰지 않으면 멈춤 |
| Vercel | 무료(Hobby)는 비상업용이고, 비공개 저장소에 다른 팀원이 푸시하면 배포가 막힘 |
| Render | 무료 웹 서비스는 15분 쉬면 잠들고(깨는 데 1분), 무료 Postgres는 30일 뒤 만료, 무료 디스크는 지워짐 → 결국 유료 필요 |
| 가상 서버(VPS) 직접 운영 | 회사 납품용 방법으로 [deploy.md](deploy.md)에 정리. 한 달 데모에는 서버 관리 부담이 큼 |
