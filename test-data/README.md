담당: 박형우 · 발표 5주차 12장 "상품 Q&A, AI 테스트 질문 17개 → 50개"

웹사이트 개발 전 기준 자료로 쓰는 초안이다. 상품·품목 기준표 데이터가 나오면 `근거` 값을 채우고, 개발 담당이 정한 형식(CSV/JSON/SQL)으로 옮긴다.
CSV는 엑셀·구글 시트에서 한글이 깨지지 않도록 UTF-8(BOM)으로 저장한다.

## test-questions.csv

목표: 50개 중 90% 이상을 맞게 답하거나 바르게 넘기기, 지어낸 가격·정책 0건.

| 분류 | 번호 | 기대 행동 (발표 7장 AI 상담 단계) |
|---|---|---|
| 상품 정보 (가격·당도·품절·개수) | 1–15 | DB 값 그대로 · AI 호출 0회 |
| 보관·신선도 | 16–30 | AI 답변 · 품목 기준표(`items`) 근거 |
| 레시피 | 31–40 | AI 답변 · 품목 기준표(`items`) 근거 |
| 넘김 (환불·건강 판단·대량 구매 등) | 41–50 | 담당자 넘김 · 정해진 답 · AI 호출 0회 |

칸 설명:
- **질문**: 손님이 실제로 칠 법한 말투로. 같은 내용을 다른 말투로 바꿔 넣어도 좋다 ("많이 달아요?" / "당도 몇이에요?").
- **기대 답**: 챗봇이 해야 할 답의 요지. 정확한 문장이 아니라 들어가야 할 내용.
- **근거**: 기대 답이 나온 DB 위치와 값 (예: `products: 사과 선물세트 brix 14.8, 측정일 10/20`). 넘김 질문은 어떤 규칙으로 넘기는지.
- **판정 기준**: 채점할 때 맞았다고 볼 조건. 넘김 질문은 "판단하는 말이 없는지"를 꼭 넣는다.
- **비고**: 출처(발표 데모 번호, 기존 17개 중 몇 번 등)나 메모.

"지어낸 가격·정책 0건"을 시험하는 질문을 일부러 넣었다: 없는 상품(14), DB에 없는 정보(10), 할인 요구(44), 지시 무시 시도(48). 같은 내용을 다른 말투로 묻는 질문(9, 27)과 추천 조건 질문(6)도 있다.

## product-qna.csv · b2b-inquiries.csv

- 실제 개인정보는 쓰지 않는다. 연락처는 `010-0000-0000`, 이름·회사는 `[예시]`를 붙인다.
- 판매자 답변, 가격, 납품 조건, 환불 정책처럼 **기업이 정해야 하는 내용은 지어내지 않고** `[판매자 확인 후 작성]`으로 둔다.
- `처리 상태` 값(접수/처리 중/완료 등)은 개발 담당에게 확인한다.
