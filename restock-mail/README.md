# 재입고 알림 (이메일)

품절 상품에 고객이 이메일을 남기면, 재고가 다시 들어오는 순간 자동으로 알림 메일을 보내는 기능입니다.
테스트용 상품 5개([예시] — 이름·가격·재고 모두 지어낸 값)와 화면(상품 목록 · 관리자 재고 관리 · 발송 기록)이 함께 들어 있어서 바로 실행해 볼 수 있습니다.

## 바로 실행해 보기

Node.js 20 이상이 필요합니다.

```bash
npm install
npm start          # → http://localhost:3065
```

`.env` 없이 실행하면 **테스트 모드**로 동작합니다. 메일이 실제 메일함으로 가지 않고
[Ethereal](https://ethereal.email)(테스트용 가짜 메일함)으로 가며, 화면 아래 **발송된 메일** 표의
"메일 보기 ↗" 링크로 받은 메일을 확인할 수 있습니다. 이메일 주소는 `test@example.com` 처럼 아무거나 넣어도 됩니다.

### 테스트 순서
1. 품절 상품(한라봉 · 참외 · 사과)에 이메일을 넣고 **알림 신청** → 신청 확인 메일 발송
2. **관리자 · 재고 관리**에서 그 상품 재고를 1 이상으로 **적용** → 재입고 알림 메일 발송
3. **데이터 초기화** 버튼으로 처음 상태로 되돌릴 수 있습니다.

## 실제 메일로 보내기

```bash
cp .env.example .env
```

`.env` 의 `SMTP_HOST`, `SMTP_USER`, `SMTP_PASS`, `MAIL_FROM` 을 채우고 서버를 다시 켜면 됩니다.
Gmail 은 일반 비밀번호가 아니라 **앱 비밀번호**(구글 계정 → 보안 → 2단계 인증 → 앱 비밀번호)를 써야 합니다.
`BASE_URL` 은 메일 속 "지금 구매하기" · "신청 취소" 링크 주소이니 실제 도메인으로 바꿔주세요.

## 알림 규칙

| 상황 | 동작 |
|---|---|
| 품절 상품에 알림 신청 | 신청 저장 + 신청 확인 메일(취소 링크 포함) |
| 같은 이메일로 같은 상품 재신청 | 거절 (중복 방지) |
| 재고가 있는 상품에 신청 | 거절 |
| 재고 0 → 1 이상 | 대기 중인 신청자 **전원에게 1회** 재입고 메일 |
| 재고 5 → 10 (이미 재고 있음) | 발송 안 함 |
| 메일 발송 실패 | 그 신청은 대기 상태로 남아 다음 재입고 때 다시 발송 |
| 확인 메일의 취소 링크 클릭 | 신청 취소, 재입고 메일 안 감 |

## 폴더 구성

```
src/
  server.js          서버 실행, API 주소 정의
  restock.js         핵심 로직 (신청, 재고 변경, 재입고 시 발송)
  mail-templates.js  메일 제목·본문 ← 문구/디자인 수정은 여기서
  mailer.js          메일 발송 설정 (SMTP 또는 테스트 메일함)
  store.js           데이터 저장 (데모용 JSON 파일: data/data.json)
public/index.html    데모 화면
test/                자동 테스트 (npm test)
```

## API

| 메서드 | 주소 | 설명 |
|---|---|---|
| GET | `/api/products` | 상품 목록 (+ 상품별 알림 대기 인원) |
| POST | `/api/products/:id/subscribe` | 알림 신청. 본문 `{ "email": "..." }` |
| GET | `/api/unsubscribe/:token` | 신청 취소 (확인 메일 속 링크) |
| PATCH | `/api/admin/products/:id/stock` | 재고 변경. 본문 `{ "stock": 10 }` → 품절→입고면 메일 발송 |
| GET | `/api/admin/mail-log` | 최근 메일 발송 기록 (최대 100건) |
| POST | `/api/admin/reset` | 데모 데이터 초기화 |

오류는 `{ "error": "사용자에게 보여줄 한국어 메시지" }` 형태로 돌려줍니다 (400 · 404 · 409).

## 우리 쇼핑몰에 붙일 때 해야 할 일

1. **저장소를 DB로 교체** — `src/store.js` 를 같은 함수 이름(`getProduct`, `updateStock`, `addSubscription`,
   `pendingFor`, `markNotified` 등)으로 DB 버전으로 다시 만들면 나머지 코드는 그대로 쓸 수 있습니다.
   신청 테이블에는 `(상품ID, 이메일, 상태)` 기준 중복 방지 제약을 거는 것을 권장합니다.
2. **재고 변경 지점에 연결** — 쇼핑몰에서 재고를 바꾸는 곳(관리자 화면, 입고 처리 등)에서
   `restock.setStock(상품ID, 새재고)` 를 호출하면 됩니다. 재고를 직접 DB에서 바꾸면 메일이 나가지 않습니다.
3. **관리자 인증 추가** — `/api/admin/*` 는 데모라서 로그인이 없습니다. 반드시 관리자만 쓸 수 있게 막아주세요.
4. **대량 발송 고려** — 지금은 신청자에게 한 명씩 순서대로 보냅니다. 신청자가 수백 명 이상이면
   발송 큐(작업 대기열)나 메일 발송 서비스(SES, SendGrid 등) 사용을 검토하세요. Gmail 은 하루 발송량 제한이 있습니다.
5. 데모 화면(`public/index.html`)과 `/api/admin/reset` 은 실서비스에서는 빼면 됩니다.
